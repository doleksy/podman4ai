podman4ai Architecture

All AI agent work runs in a per-project Sandbox inside a dedicated Hyper-V VM. Windows only ever sees an editor interface and the ports you choose to open, and the internet is reachable only through each project's Egress proxy.

Decisions

AreaDecisionADR
Threat modelDamage to the Host, credential and data leaks, and supply-chain malware, at a home-lab level. Safe to run with prompts off.
Sandbox machineDedicated Podman machine on Hyper-V: 12 GB, 6 CPUs, 200 GB. WSL2 stays for everything else.0004
SourceA Project volume per project, cloned from GitHub. No Windows path is ever mounted.0001
ConfigurationThe Launcher owns it, from Host settings. No devcontainer.json, and nothing an Agent can write to defines the boundary.0002
NetworkPer-project internal network and Egress proxy, allowing domain names on the Allowlist. Added only by you, with p4a allow.0003
HardeningRootless, all capabilities dropped, no-new-privileges, non-root user, no sudo, no Podman socket, limits of 4 GB / 4 CPUs / 4096 processes.
SecretsAgent token from claude setup-token and a Repo token per project, stored as Podman secrets and mounted as files.
Base imageAnthropic's reference Dockerfile, adapted: Debian, Node, Python with uv, Bun, tmux, gh. No zsh and no in-container firewall.
Claude baselineSettings and plugins (context-mode, mattpocock-skills) versioned in podman4ai and baked into the image. Memory stays per Sandbox.
WorkingVS Code attaches to the Sandbox; Visual Studio is ruled out.0001
SessionsSessions run in tmux via p4a claude. Commits use your name with a Co-Authored-By line.
Updatesp4a image build, then p4a recreate. Claude's self-updater is off.
Testingbats unit tests with a stand-in podman, plus integration tests you run on the Host before merging.
